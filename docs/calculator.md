# «Посчитай» — калькулятор голосом, контракт

Правила общей работы — как в `docs/voice-pipeline.md` («Правила для всех»): одно дерево,
правь только свои файлы, `cargo check --all-targets` зелёный всегда, не коммить, вопросы —
`orca orchestration ask`, на «СТОП» от координатора — немедленно прекратить правки.

## Статус (2026-09-26)

Реализовано, инсталлятор 0.1.7. Живая проверка `examples/calc_probe`: «33*78=» в калькуляторе
Windows → 2 574, повторный ввод в открытый калькулятор ~0,2 с. Замер (`examples/eval.rs`, 166 фраз):
165/166; калькулятор 12/12 (включая «15 процентов от двухсот» и «7 в квадрате»), с паузой 2/2,
английский 1/2 (провал — английская фраза русским голосом RHVoice).

Решения:
- Порядок действий: калькулятор в обычном режиме считает по порядку ввода, поэтому `calc`
  переставляет множители или, если без скобок никак, ставит их — и только тогда `calcapp`
  переключает калькулятор в инженерный режим (Alt+2); в остальных случаях режим пользователя
  не трогается. Проверка режима — по отправке Alt+2 и удержанию фокуса (без UI Automation).
- Кандидаты цели: `route` отдаёт русский и английский варианты; берётся первый, который
  разобрался как выражение, — так определитель языка, ошибочно выбравший английский на русских
  числах, не ломает подсчёт.
- `textnorm`: косвенные падежи числительных («двухсот», «пятидесяти», «тысячу») → цифры.

## Требование пользователя (2026-09-26)

«ривер посчитай 33 умножить на 78» — Reever открывает калькулятор Windows, вводит выражение
и калькулятор показывает ответ.

## Что уже сделал координатор (фаза 0)

- `grammar.rs`: `IntentKind::Calc`, в `defaults()` намерение `calc` — «посчитай», «сколько будет».
- `dispatch.rs`: `Route::Calc(Vec<String>)` (кандидаты выражения: цель `text`, затем `alt`),
  `route()` его выдаёт; в `dispatch()` — заглушка.
- `calc.rs`: `CalcExpr { keys, pretty, value }`, `parse_expression(text) -> Option<CalcExpr>` — заглушка.
- `calcapp.rs`: `open_and_type(keys) -> Result<()>` — заглушка.

## Поведение

1. `route` → `Route::Calc(cands)`; «посчитай» без цели — незаконченная команда (Engine дослушает).
2. `dispatch`: первый кандидат, для которого `calc::parse_expression` вернул `Some`, →
   `calcapp::open_and_type(expr.keys)`; лог «🧮 33 × 78 = 2574» (значение — если посчитано;
   с учётом `private_log` — только «🧮 считаю»). Ничего не разобралось → «⚠ не понял выражение
   «…»», `Done(false)`. Офлайн-режим не мешает.
3. `parse_expression` (чистая, тесты): текст уже нормализован `textnorm::normalize` (числа
   словами → цифры: «тридцать три» → «33»; проверь, что так и есть, и что «две целых пять
   десятых», «полтора», «ноль» обрабатываются). Операции: плюс/прибавить/прибавь/сложить с, минус/
   отнять/вычесть/без, умножить на/умножь на/помножить на/на (в «33 на 78» — умножение), разделить на/
   делить на/поделить на, процент(ов/а) от («15 процентов от 200» → `200*15%`), в квадрате/в кубе/
   в степени; английские plus/minus/times/multiplied by/divided by/over/percent/squared; десятичные
   «запятая»/«точка»/«и» между числами — только когда однозначно. Отрицательные («минус 5 плюс 3»).
   Не арифметика → `None`. `keys` только из разрешённых символов (см. doc-комментарий).
4. `open_and_type`: калькулятор — UWP `CalculatorApp.exe` (запуск через `calc.exe` или
   `shell:AppsFolder\Microsoft.WindowsCalculator_8wekyb3d8bbwe!App`); если уже открыт — взять его
   окно; дождаться окна (до ~3 с), вывести на передний план (см. `winutil` — `AttachThreadInput`
   для обхода запрета смены foreground), **убедиться, что активно именно окно калькулятора**,
   сбросить ввод (`Esc`), набрать `keys` через `SendInput` (`KEYEVENTF_UNICODE`), с небольшой паузой
   между символами если нужно. Если в любой момент активным стало другое окно — прекратить ввод
   и вернуть ошибку.
