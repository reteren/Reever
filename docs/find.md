# «Ривер найди …» — поиск файлов и папок с окном выбора

## Статус (2026-10-02)

Реализовано, инсталлятор 0.2.7 (0.2.6 — первая сборка, без исправлений ревью и нечёткого поиска). Тесты: `find` (варианты запроса, сходство имён, номер голосом),
`dispatch::find_phrases_pick_the_scope_by_the_longest_trigger`, `engine` (режим выбора). На живом
Everything (`examples/find_probe`) «проджект джиэсти» — так GigaAM услышала «project GST» —
первым находит `C:\-PROJECT.GST-`.

## 0.2.8

- «папка X» и «открой папку X» идут тем же путём, что и «найди папку X»: окно выбора, если
  совпадений несколько. Раньше открывался «лучший» вариант сразу: «my stuff» открывал кэш в
  Videos, «working» — папку Steam. Алиасы папок (aliases.json) добавляются вариантами запроса.
- Одно неверно услышанное слово: если хороших совпадений меньше трёх, запрос повторяется без
  каждого из слов по очереди (ранг 0,75). «alt debug message» → `C:\hive\old debug message
  (do not touch)`.
- Слабые случайные совпадения (< 0,45) прячутся, если есть хорошие.
- Окно проверено вживую в приложении (`REEVER_FIND_DEMO="запрос"` — показать окно без
  микрофона): центр экрана, поверх окон, 40 вариантов.

## Формат файла: «найди X формат Y»

- Всё до слова «формат» (format, расширение, extension) — имя, после — формат
  (`find::split_format`). «Найди X формат» + пауза — Reever дослушивает
  (`Grammar::is_incomplete`).
- Формат сопоставляется только с закрытым словарём (`find::FORMATS`, ~55 форматов) — так
  устроено «усиление»: модель не переобучается, но после «формат» любое услышанное ищется
  только среди форматов и их произношений. Порядок:
  1. точное расширение или русское произношение: «екзе», «игзи» → exe; «джсон», «jason» → json;
     «пу», «пай», «питон» → py;
  2. латиница вне словаря — как есть («heic», «webm»);
  3. названия букв («пи эн джи» → png);
  4. ближайшее по сходству в словаре (≥ 0,75).
- В Everything уходит `file: ext:<ext> <имя>`. Без имени («найди формат джсон») — свежие файлы
  формата.
- Проверено синтезированной речью через Engine: «ривер формат игзи» → exe, «экшн с формат
  джейсон» → json, «мэйн формат пай» → py, «отчет формат пдф» → pdf. На живом Everything
  «reever формат екзе» находит reever.exe, «actions формат jason» — actions.json.
- Формат не распознан — в журнале «⚠ формат не распознан: «…»», поиск не идёт.

## Команды (грамматика v8)

- «найди …», «найти …», «поищи …» — файл или папка (`find`).
- «найди папку …» — только папки (`find_folder`).
- «найди файл …» — только файлы (`find_file`).

Выигрывает самая длинная фраза, поэтому «найди папку X» — это всегда папка.

## Как ищет (`find.rs`)

- Варианты запроса, не больше четырёх: русский текст и английский текст (вторая модель), плюс
  два транслита русского — «английский» («проджект» → project: дж→j, кт→ct, кс→x) и буквальный.
- Названия латинских букв, в том числе склеенные ASR, становятся буквами: «джи эс ти»,
  «джиэсти» → gst. Язык заранее не угадывается: ищутся все варианты, а какой совпал, решает
  сам Everything. Это главный ответ на «русский или английский».
- На каждый вариант три запроса к Everything HTTP, все с `ignore_punctuation=1` и
  `ignore_whitespace=1` (параметры плагина HTTP Server 1.5):
  - `wfn:<без пробелов>` — имя целиком;
  - `startwith:<без пробелов>` — начало имени;
  - сами слова — вхождение.
  Так «project gst» находит «-PROJECT.GST-».
- Ранг = сходство имени (целиком 1,0 / начало / вхождение / Jaro-Winkler) + частота − шум:
  - частота — история открытий через Reever (`usage.json`: число и давность) и недавние
    Windows (`%APPDATA%\Microsoft\Windows\Recent\*.lnk`);
  - шум — AppData, Windows, node_modules, .git, target, Temp, а слабее — Program Files,
    steamapps, .vs.
- «Часто открываемые» (добавка ≥ 0,15) идут первым разделом, до 40 вариантов.

## Нечёткий и пословный поиск (0.2.7)

- Произнесённая пунктуация убирается из запроса: «точка», «дефис», «подчёркивание», dot, dash.
- Пословный запрос для смешанных имён: каждое русское слово — «основа | латиница | ф→ph».
  Например, `делов|delovie партне|partneri фотош|fotoshop|photoshop`. Всё, что он нашёл,
  совпало по всем словам: ранг ≥ 0,85.
- Меньше трёх хороших совпадений — нечёткий проход. Берутся имена с теми же первыми 3–4
  буквами, до 500 штук, и отбираются по сходству Jaro-Winkler ≥ 0,82: «меморволд» →
  Memory_Vault, «билингол» → bilingual.

## Выбор

- Одно совпадение — открывается сразу: папка в Проводнике, файл программой по умолчанию.
- Несколько — окно `picker` (`frontend/picker.html`) в центре экрана поверх всех окон. Выбор:
  - голосом — «третий», «номер два», «5», «second», 15 с (`EngineConfig::choice_wait_ms`);
  - мышью — двойной клик;
  - клавиатурой — стрелки и Enter, цифры 1–9; Esc закрывает окно.
  «Ривер …» вместо номера — новая команда, окно остаётся для мыши.
- Открытое записывается в `usage.json`, и в следующий раз оно выше.

## Ограничения

- Нужен Everything 1.5 с плагином HTTP Server на 127.0.0.1:8011 (docs: KNOWLEDGE про плагин).
- Частота из Everything (`runcount:`) не используется: по HTTP она закрыта
  `allow_query_access` и не сортируется.
- Имя, которое ни одна модель не услышала близко («reever» → «ривр», «yeah»), не найдётся —
  нечёткого поиска по всему диску нет.
