# Перенос интерфейса с WebView2 на нативный

Дата: 2026-11-01. Решение пользователя: интерфейс Reever целиком уходит с WebView2. Перенос идёт
по окнам, после каждого этапа программа рабочая и выпускаемая.

## Зачем

- WebView2 Manager держит ~180 МБ, пока жив хоть один веб-вид (в трее его держит окно маскота).
- Окно открывается без запуска веб-движка (сейчас 0,3–1 с), маскот появляется сразу.
- Нет прослойки IPC окно ↔ Rust: меньше рассинхрона (история маскота и пузыря), меньше задержек.
- Плавнее перетаскивание и анимации прозрачных окон.
- Нет зависимости от версии и сбоев WebView2.

## Основа: что выбрано и почему

**Direct2D + DirectWrite + WIC + DirectComposition** через уже подключённый крейт `windows`
(0.58). Своё дерево виджетов поверх.

- **DirectWrite** решает самое трудное из списка рисков: арабский (форма букв, справа налево),
  подбор системного шрифта для иероглифов, ClearType, свои шрифты (Martian Mono, Handjet,
  Geologica) из памяти.
- **WIC** декодирует WebP/PNG спрайтов и рамок средствами Windows — без новых зависимостей.
- **DirectComposition** даёт прозрачные окна с попиксельной альфой без перерисовки всего
  окна системой (сейчас это делает WebView2 + `skin.rs`).
- **Шейдер рамки** (frame.js, WebGL2) переносится в HLSL-эффект Direct2D (или D3D11 пиксельный
  шейдер на ту же поверхность DirectComposition).
- **Ввод текста**: своё поле + IMM32/TSF для ввода иероглифов (окно кандидатов у курсора).
- **Специальные возможности**: `accesskit` + `accesskit_windows` на сырой HWND.
- **Правила чисел** (1 фраза / 2 фразы / 5 фраз) — таблица правил CLDR для 30 языков интерфейса
  (крейт `intl_pluralrules` или своя таблица); названия языков и даты — `GetLocaleInfoEx`.

Почему не готовые библиотеки интерфейса: egui перерисовывает всё окно каждый кадр и плохо
знает арабский; у iced и Slint слабый ввод иероглифов и стиль под наш дизайн всё равно рисуется
вручную; у Slint ещё и условия лицензии. Наш дизайн — кастомная рамка, шейдер, спрайты —
стандартные виджеты почти не использует, поэтому выигрыш библиотек мал, а ограничения реальны.
**Проверка решения** — этап 1: маскот на этой основе с замерами. Если замеры плохие, выбор
основы пересматривается до главного окна.

## Правила переноса

1. **Одно окно — один этап.** Новое окно включается настройкой-флагом `native_<окно>`,
   по умолчанию выключено, пока не пройден чек-лист соответствия; потом флаг включается по
   умолчанию, а старая веб-версия удаляется в следующем этапе (не в том же).
2. **Источник правды о состоянии — Rust.** Нативные окна получают состояние вызовами и каналами
   внутри процесса, а не событиями `reever://*`. Существующие события остаются для ещё не
   перенесённых веб-окон.
3. **Строки интерфейса — один источник.** Переводы переезжают из `frontend/i18n/locales/*.js`
   в JSON, который читают и веб-окна (пока живы), и Rust. Ключи не дублируются.
4. **Замер до и после.** Каждый этап фиксирует RAM (рабочий набор + WebView2), CPU в покое и при
   анимации, время появления окна. Числа — в `docs/research/native-ui-measurements.md`.
5. **Кадры.** Перерисовка только при изменении (как сейчас у рамки), лимит частоты кадров
   из настройки «Плавность» уважается, во время перетаскивания анимации стоят.
6. **DPI.** Per-monitor v2, все размеры в DIP, перенос окна между мониторами без размытия.

## Этапы

### Этап 0. Основа (≈1 неделя) — параллельно две ветки работ

**0a. Нативное ядро окон** — `src-tauri/src/native/`:
- поток окон с собственным циклом сообщений (Tauri пока остаётся и живёт рядом);
- окно на DirectComposition (прозрачное, без рамки, поверх всех, без фокуса — для маскота);
- устройство Direct2D/D3D11, восстановление после потери устройства (смена видеокарты, сон);
- загрузка спрайтов через WIC в кэш битмапов под текущий масштаб;
- DirectWrite: свои три шрифта из встроенных байт + системный подбор для иероглифов;
- таймер кадров с учётом лимита и паузы.

**0b. Строки интерфейса для Rust**:
- `frontend/i18n/locales/*.js` → `i18n/locales/*.json` (один источник), веб-окна читают JSON;
- модуль `ui_text.rs`: `t(key, params)`, правила множественного числа, направление письма;
- `scripts/check-i18n.mjs` проверяет JSON; тест Rust — все ключи всех 30 языков на месте.

### Этап 1. Маскот (≈1 неделя) — главный выигрыш памяти

Повторить `frontend/mascot.html` + `skin/mascot.js` нативно: кадры спрайта, свечение
(уменьшенные копии + размытие эффектом Direct2D), жидкость в глазу по уровню микрофона,
вспышка на «услышал», состояния idle/listening/busy/paused, глаз «слушаю» по wake,
приход/уход, перетаскивание и закрепление места, клик по голове (попиксельная проверка
альфы), режимы never/commands/always, размер, intro. `mascot.rs` вызывает нативное окно
вместо `emit("mascot://…")`. После этапа в трее нет ни одного веб-вида.

**Ворота:** замер RAM/CPU против веб-маскота; если нативный хуже по CPU — разбор до этапа 2.

### Этап 2. Пузырь с текстом (≈3 дня)

`bubble.html` → нативный: текст через DirectWrite (все 30 языков, арабский справа налево),
появление/исчезание, позиция у маскота, intro-реплики.

### Этап 3. Окно выбора и подтверждение (≈1 неделя)

`picker.html`, `confirm.html`: список с клавиатурой и мышью, рамка `picker_frame.webp`,
фокус, Esc/Enter, специальные возможности. Первые нативные элементы управления: кнопка,
список, прокрутка.

### Этап 4. Главное окно (≈3–4 недели)

1. Каркас: фигурная рамка, кнопки окна, шейдер рамки, перетаскивание, свёртка, лёгкий вид.
2. Главная: сфера с частицами (orb.js), журнал, состояние, эквалайзер.
3. Поле ввода (с IME), выпадающий список, переключатель, ползунок, подсказки.
4. Действия: список, редактор, фразы, калибровка, сканер программ.
5. Настройки: все группы, мгновенное применение, языки, звуки, плавность.
6. «Что можно сказать» (грамматика), журнал.
7. Первый запуск («скажите ривер»), плашка языкового пакета.

### Этап 5. Уход с Tauri (≈1 неделя)

Трей (`Shell_NotifyIcon`, меню уже своё — `traymenu.rs`), глобальная клавиша
(`RegisterHotKey`), автозапуск (ключ Run в реестре), один экземпляр, установщик NSIS без
WebView2. Удаляются `tauri`, плагины, `frontend/`.

**Условие перед удалением веб-окон:** нативные окна должны уметь и лёгкий вид (`lite_ui`,
lite.css: плоская металлическая панель вместо хромовой рамки). Пока его нет, окна выбора и
подтверждения в лёгком интерфейсе остаются веб даже при `native_dialogs` (этап 3).

## Чек-лист соответствия окна (перед включением флага по умолчанию)

- Внешне совпадает с веб-версией на скриншотах при 100 % и 150 % масштаба.
- Все состояния и переходы из старого JS повторены; события в журнале те же.
- RAM/CPU/время появления замерены и не хуже.
- 30 языков: арабский справа налево, иероглифы без квадратиков.
- Тесты `cargo test --lib` проходят, `check-i18n` проходит.
