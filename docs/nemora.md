# Немора — музыкальные команды

Немора — музыкальный плеер того же автора. Если она установлена, у Reever появляются
музыкальные команды; если нет — их не видно в «Что можно сказать» и они не сравниваются с
речью. Ни кнопок, ни настроек: и в Reever, и в Неморе ничего включать не нужно.

Код — `src-tauri/src/nemora.rs`, команды в грамматике — `IntentKind::Music` с полем
`music: MusicOp` (`grammar.rs`, версия 16; громкость — версия 17).

## Как Reever находит Немору

`nemora::find_mcp()` ищет `nemora-mcp.exe` по порядку:

1. переменная `REEVER_NEMORA_MCP` — путь к своей сборке Неморы (разработка);
2. запись установщика `Software\Microsoft\Windows\CurrentVersion\Uninstall\Nemora` →
   `InstallLocation` в HKCU, затем в HKLM (путь там в кавычках — они срезаются);
3. `%LOCALAPPDATA%\Nemora`.

Проверка — чтение реестра и одного файла, поэтому её не кэшируют надолго (`RECHECK` = 5 с).
Повторяется при запуске, раз в 10 с в аудио-потоке (`nemora::tick`) и при открытии главного
окна. Поставили или удалили Немору при запущенном Reever — команды появятся или исчезнут без
перезапуска, в журнале строка «Немора найдена» / «Неморы больше нет».

## Команды (по умолчанию)

| Скажи | Что произойдёт | Немора закрыта |
|---|---|---|
| `ривер включи трек X` · `трек X` · `включи песню X` · `play song X` | трек, за ним вся библиотека в Smart Shuffle | запускается |
| `ривер включи исполнителя X` · `play artist X` | все его песни вперемешку | запускается |
| `ривер включи альбом X` · `play album X` | альбом по порядку треков | запускается |
| `ривер включи плейлист X` · `play playlist X` | плейлист по порядку; «избранное» — избранное | запускается |
| `ривер включи музыку` · `play music` | остановлено — продолжить; играет — не трогать; иначе вся библиотека в Smart Shuffle | запускается |
| `ривер выключи музыку` · `останови музыку` · `pause music` | пауза Неморы (не переключатель) | медиа-клавиша, как «пауза» |
| `ривер смарт шаффл` · `smart shuffle` | Smart Shuffle | «Немора не запущена» |
| `ривер перемешай` · `включи шаффл` · `shuffle` | обычное перемешивание | «Немора не запущена» |
| `ривер выключи перемешивание` · `выключи шаффл` · `shuffle off` | перемешивание выключено | «Немора не запущена» |
| `ривер лайкни` · `в избранное` · `like song` | играющий трек — в избранное | «Немора не запущена» |
| `ривер что играет` · `what's playing` | «сейчас играет: исполнитель — название» в журнал | «Немора не запущена» |
| `ривер громкость 50` · `громкость семьдесят пять` · `volume 30` | громкость самой Неморы (её ползунок, не Windows), 0–100; «максимум», «ноль» | «Немора не запущена» |
| `ривер громче` · `тише` · `volume up` / `down` | громкость Неморы на шаг из настроек (10 %) | «Немора не запущена» |

Правило: команды, которые **начинают** музыку, запускают Немору (её `play` ждёт запуска до
40 с); команды, которые **меняют текущее**, её не запускают. «Пауза», «следующий трек»,
«предыдущий трек» и «заново» остаются системными командами (медиа-клавиши): Немора получает их
через системные медиа-кнопки Windows (SMTC), и они работают и с любым другим плеером.

Одно нажатие «назад» плееры понимают как «этот трек сначала», если он уже поиграл (Немора — после
5 с, Spotify — после 3 с). Поэтому «предыдущий трек» нажимает дважды, а «заново» — один раз.
Когда Немора установлена и играет, обе команды идут через неё: «заново» — `seek 0`,
«предыдущий» — `previous_song`, второй раз только если трек не сменился. Медиа-клавиша не знает,
сколько трек играл, и сразу после «следующего» ушла бы на два трека назад.

Фразы правятся в «Что можно сказать» → «Изменить», как у остальных команд. У каждой «включи …»
есть пара «выключи …»: слова отличаются одной буквой, а сравнение нечёткое, и без пары
«выключи музыку» совпадало бы с «включи музыку» (тест `switching_on_and_off_are_never_confused`).
Команды без цели («лайкни», «что играет», «выключи музыку») выполняются, не дожидаясь полной
паузы, как команда с известной целью.

## Настройки (Настройки → Немора)

Группа видна, только пока Немора установлена; поля — `Settings::nemora_*` (config.rs), в
команду их переносит `nemora::Options`. Сохранение, как у всех настроек, перезапускает
распознавание, и следующая команда идёт уже с новыми значениями.

| Настройка | Варианты (первый — по умолчанию) |
|---|---|
| Музыкальные команды Неморы | вкл / выкл — выключено: команды скрыты, как будто Неморы нет; под переключателем — найденный путь |
| После «включи трек X» | дальше вся библиотека в Smart Shuffle · дальше вся библиотека, перемешивание как было · дальше песни этого исполнителя · повторять этот трек · только этот трек |
| «Включи исполнителя X» | вперемешку · сначала самые слушаемые · по альбомам |
| Альбомы и плейлисты | по порядку · вперемешку |
| «Включи музыку», когда ничего не на паузе | вся библиотека в Smart Shuffle · избранное вперемешку · самые слушаемые (200) вперемешку · недавно добавленные (200) |
| Шаг «громче» / «тише» | 5–25 %, 10 % |
| Запускать Немору, если она закрыта | вкл — выключено: «включи …» отвечают «Немора не запущена» |
| Включать только уверенные совпадения | выкл — включено: похожесть ≥ 0,8 и без запасного первого результата поиска |
| «Предыдущий трек» и «заново» через Немору | вкл — выключено: медиа-клавиши, как для любого плеера |
| «Выключи музыку» ставит на паузу другой плеер | вкл — выключено: без играющей Неморы «в Неморе ничего не играет» |

«Повторять этот трек» и «только этот трек» ставят в Неморе повтор «один» / «выкл». Прежний режим
Reever запоминает и возвращает на следующей команде воспроизведения, иначе следующий альбом
крутил бы по кругу свою первую песню. «Перемешивание как было» читает режим до команды: `play`
без перемешивания выключает в Неморе оба режима, и Reever включает прежний обратно.

## Как выполняется команда

- Reever — MCP-клиент: запускает `nemora-mcp.exe` дочерним процессом без окна, говорит
  JSON-RPC строками по stdin/stdout (протокол `2025-06-18`), имя клиента — `Reever`. Процесс
  живёт 5 минут без дела, потом закрывается; умер — перезапускается при следующей команде.
- Внутренний канал Неморы (именованный pipe) Reever не трогает: MCP — описанный контракт, и
  nemora-mcp сам читает библиотеку без запущенной Неморы, запускает её и проверяет доступ.
- Команда идёт в своём потоке (`DispatchResult::Background`), аудио-поток не ждёт её.
  Звук успеха или ошибки — когда она закончится (`nemora::take_outcomes`).
- Сначала `app_status`: он не запускает Немору и говорит, открыта ли она и что разрешено
  агентам. «Read» или «Nothing» в Немора → Настройки → AI agents — в журнале «Немора не даёт
  агентам управлять».

### Что именно играет

- **Два варианта названия.** Многоязычная модель во фразе «включи трек ай рили лайк ю парт
  ту» пишет английское название кириллическим транслитом. Поэтому, когда название записано
  кириллицей, отрезок с ним (по таймингу слов, `bilingual::resolve_with`) переслушивается моделью
  английского языка из набора (`AsrSet::transcribe_language`) — у одной многоязычной модели это
  она же, но одно название без русских слов вокруг она пишет латиницей (замер 2026-11-22:
  «I really like you part too»). Латинский вариант идёт вторым (`alt`), ищут по обоим.
- **Выбор.** По выдаче `search` для каждого варианта: точное совпадение названия важнее всего,
  иначе самое похожее (≥ 0,6), иначе первый результат — выдача Неморы ранжирована, опечатки,
  раскладку и кириллические чтения японского она понимает сама. Первый результат берётся,
  только если он хоть немного похож (≥ 0,3) или его не сравнить по буквам (японское, китайское
  название): на транслите поиск отдаёт случайное («дэд матрикс» → «i fvcked up my happiness…»,
  0,12), и тогда в журнале «не нашлось», а не чужой трек.
- **Похожесть** — лучшее из двух сравнений: вариантов по Левенштейну и фонетических ключей —
  без пробелов (слитное «DEADMATRIX» = «дэд матрикс»), со сведёнными гласными (е э и ы й → и,
  ю → у, я о → а), со схлопнутыми повторами букв (у латиницы — до транслитерации: «Fluxxwave»
  = «флуксвав»). Запрос, целиком входящий в название, — не меньше 0,7, тем больше, чем большую
  часть названия он покрывает («спидап» отличает «Fluxxwave (Sped Up)» от «(Lay with Me)»).
- **Вся библиотека.** Транслит английского («хейт мьюзик») поиск Неморы не понимает. Если
  точного совпадения нет, а название сказано кириллицей или латинский вариант ничего похожего
  не нашёл, Reever сравнивает его со всеми названиями библиотеки (`list_songs` /
  `list_artists` / `list_albums` по страницам; у треков — и «исполнитель название»).
  Транслитерация Reever фонетическая: «Hate Music» = «хат мьюзик» (0,82 против 0–0,2 у
  чужих названий). На 1785 песнях это ~0,15 с.
- **Общий вид названий** перед сравнением: «Pt.» и «pt2» — «part 2», «Vol.» — «volume», номер
  части словами — цифрой (только после part/парт/vol/часть: в остальных местах «ту» — это
  «to»), пометки в скобках отбрасываются вторым вариантом («Nevermind (Deluxe Edition)» =
  «невермайнд»).
- **Трек** играет первым, за ним `play` всей библиотеки и `set_shuffle smart`: без этого `play`
  делает очередь ровно из переданных треков, и после одного трека наступила бы тишина.
  Версии (slowed, reverb) пропускаются, если в выдаче есть сам трек.
- **Исполнитель / альбом**: песни — `list_songs` по страницам (до 200 за вызов) по
  `artist:<имя>` / `album:<ключ>`.
- **Плейлист**: поиск Неморы отдаёт только имена плейлистов, поэтому id берётся из
  `list_playlists` (точное имя, вхождение, затем похожесть ≥ 0,85).
- «;» вычищается из запроса: Немора делит по нему запрос на несколько.

### Smart Shuffle

Немора не включает Smart Shuffle при пустой очереди и без тир-листа, отмеченного «влияет на
шаффл», а веса грузит не сразу. Поэтому Reever проверяет поле `shuffle` в ответе, через 1,5 с
перепроверяет `now_playing` и, если Smart так и не включился, включает обычное перемешивание
и пишет об этом в журнал. Любой `play` без перемешивания выключает Smart в самой Неморе —
«включи альбом» после «смарт шаффл» играет альбом по порядку.

## Что видно в Неморе

- Уведомления «Reever: …» — у воспроизведения, паузы и перемешивания; у «лайкни», следующего
  трека и громкости их нет.
- Журнал в Немора → Настройки → AI agents пишет каждую команду уровня «control» (хранит
  последние 200).
- Уровень доступа в Неморе один на всех агентов; Reever работает на её уровне по умолчанию
  («Control»).

## Проверка

```bash
cd src-tauri
cargo test --lib nemora grammar dispatch say          # разбор, пары «включи/выключи», скрытие без Неморы
cargo test --lib nemora::tests::live_read_only_calls -- --ignored --nocapture   # живой nemora-mcp, только чтение
cargo run --example nemora_probe -- "включи трек smells like teen spirit" "включи плейлист гоат"
```

`nemora_probe` проходит весь путь от фразы до найденного трека на своей библиотеке, но не
играет: очередь и плеер не трогаются.

## Не сделано

- Окна выбора при неоднозначном названии нет — играет лучший вариант, в журнале видно, какой.
- Со стороны Неморы (решает её автор): одна команда «найди и включи», тихий режим уведомлений
  или свой уровень доступа для Reever — голосовая команда пользователя, а не ИИ-агент.
