# Проба встроенного индекса дисков

Дата замеров: 2026-10-16. Проба: [`src-tauri/examples/index_probe.rs`](../../src-tauri/examples/index_probe.rs). Запуск: `cargo run --release --example index_probe -- --query=downloads --threads=8` из `src-tauri`. В системе один фиксированный том C:, NVMe WD Blue SN580 2 TB; CPU Ryzen 7 7800X3D.

## Результаты

Для проверки прав проба запускалась повторно с Windows SAFER `NORMALUSER` ([описание уровня](https://learn.microsoft.com/ru-ru/windows/win32/api/winsafer/nf-winsafer-safercreatelevel)): в `whoami /all` группа Administrators была `deny-only`, единственная включённая привилегия — `SeChangeNotifyPrivilege`. Это ограниченный пользовательский токен без доступа по членству в Administrators; его integrity level остался High. У обычного холодного прохода именно под таким токеном замера нет: его проход пришёлся на уже прогретый файловый кэш. Холодный полный проход под исходным повышенным токеном занял 92,98 с, поэтому к основным числам ниже он не приравнивается.

| Набор | Время обхода | Записей | Private bytes процесса после индекса | Имена + записи | Поиск `downloads`: подстрока / fuzzy |
|---|---:|---:|---:|---:|---|
| Всё доступное обычному пользователю | 19,76 с, прогретый кэш | 4 495 679 | 155,29 MiB | 150,48 MiB | 217 за 1,18 с / 590 за 2,66 с |
| С исключениями | 3,50 с, прогретый кэш | 2 342 147 | 82,53 MiB | 74,70 MiB | 88 за 554 мс / 449 за 1,49 с |
| Everything, процесс пользователя | — | 4 643 679 по данным задачи | 436,37 MiB измерено у запущенного процесса | — | — |

Fuzzy считает `0.6 × Jaro-Winkler` по имени и stem; порог `0.492`, как в `find.rs`. Оба поиска проходят по каждому имени, нормализуя регистр и пунктуацию. Это не замер полного ответа UI: в него не входят сборка полного пути, ранжирование по истории и недавним файлам, сериализация и показ окна. Полный fuzzy-проход по неотфильтрованному индексу немного превышает действующий бюджет поиска 2,5 с.

Снимок private bytes сделан после построения и уплощения индекса, до освобождения. В него входят арена, записи и накладные расходы процесса. Запись индекса — 12 байт: `parent:u32`, смещение имени `u32`, длина `u16`, флаги типа и резервный байт; имена лежат подряд в UTF-8-арене. Пиковая память во время обхода не измерялась: рабочие shards используют 16-байтовые временные записи и очередь путей. Результаты слегка менялись между проходами, пока система продолжала работать.

Фильтры оставили 52,1% записей обычного пользователя и сократили private bytes индекса на 46,9%. Память полного индекса примерно на 64% меньше измеренных 436,37 MiB Everything; отфильтрованного — примерно на 81% меньше. Ошибки перечисления (`FindFirstFileExW` не открыл каталог) составили 2 333 / 797; проба не классифицирует коды ошибок, поэтому это не все обязательно отказы доступа. Reparse-point-каталоги записываются, но не обходятся: 460 / 298.

Отфильтрованный проход выполнялся сразу после полного с прогретым кэшем. Холодное время отфильтрованного обхода отдельно не измерено. Отдельная проба на C: под повышенным токеном увидела 4 623 267 записей и 8 ошибок; отличие от 4 495 679 под `NORMALUSER` подтверждает, что повышенные права дают дополнительную видимость. Для обычного индекса целевые именно числа под `NORMALUSER`.

## Исключения и границы обхода

Из индексирования пропускаются `C:\Windows`, `WindowsApps`, `$Recycle.Bin`, `System Volume Information`, `node_modules`, `target`, `.git`, `%LOCALAPPDATA%\Temp`, а также каталоги с компонентами `Cache`, `Cache2`, `CacheStorage`, `Code Cache`, `GPUCache`, `ShaderCache`, `GrShaderCache`, `Service Worker`. Правила для кэшей и `target` сейчас глобальные по имени каталога: в реализации их лучше ограничить известными родителями и разрешить пользовательские исключения, иначе будут пропущены одноимённые полезные папки.

Обход вызывает `FindFirstFileExW` с `FindExInfoBasic` и `FIND_FIRST_EX_LARGE_FETCH`, перечисляет только диски `DRIVE_FIXED` и не читает содержимое файлов. Он не запрашивает повышение прав: тест под `SAFER_LEVELID_NORMALUSER` подтвердил доступ к читаемым обычным каталогам; ошибки и недоступные каталоги пропускаются. Документация Windows описывает `FIND_FIRST_EX_LARGE_FETCH` как больший буфер запросов каталогов, который может ускорить перечисление [FindFirstFileExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirstfileexw).

## Свежесть, файл индекса и нагрузка в покое

- Сохранять бинарный снимок в `%APPDATA%\com.troid.reever\index-v1.bin`: заголовок с версией формата и идентификаторами томов, затем arena имён и 12-байтовые записи. Измеренный объём без заголовка — около 150,5 MiB полностью или 74,7 MiB с исключениями; размер файла примерно такой же. Писать во временный файл и атомарно заменять основной после завершения обхода/пакета изменений.
- Оценка загрузки полного снимка: при последовательном чтении 500 MiB/s передача 150,5 MiB занимает около 0,3 с; фактическое чтение, выделение памяти и проверка файла не измерялись. На старте сначала открыть watchers, затем загрузить существующий снимок и сразу искать по нему; накопившиеся события применить поверх снимка, потом сверить тома в фоне. Это закрывает гонку между чтением файла индекса и запуском watcher, но не изменения, случившиеся пока Reever был закрыт.
- На время работы открыть по одному watcher на корень каждого фиксированного тома через `ReadDirectoryChangesW` с `bWatchSubtree=TRUE`; изменения применять пакетами и сбрасывать на диск с debounce. При переполнении буфера API возвращает нулевой `lpBytesReturned`, после чего нужен полный перескан [ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw). Пока приложение закрыто, watcher не получает события: поэтому после быстрого старта снимка всё равно нужна фоновая сверка.
- Оценка покоя: ожидающее чтение событий не опрашивает диск и почти не расходует CPU; при буфере 64 KiB — около 64 KiB пользовательского буфера на том плюс дескрипторы и память очереди. Это оценка; фактическая нагрузка watcher не измерялась. Если событие невозможно применить однозначно или буфер переполнен, ставить том на пересканирование.

## Встраивание, этап 2

1. `src-tauri/src/config.rs`: добавить `find_source = "auto" | "everything" | "local"` в `Settings`, `parse_settings` и `Default`; `auto` сохраняет поведение Everything и переключается на локальный индекс при недоступности, `local` явно включает построение.
2. Новый `src-tauri/src/local_index.rs`: компактная arena, стабильные ID и tombstone-записи для удаления, загрузка и атомарное сохранение, обход дисков, фильтры и watcher. Новую библиотечную зависимость прототипу добавлять не пришлось; в проекте уже есть `windows 0.58`, но для вызовов watcher может понадобиться включить соответствующий feature `Win32_System_IO`.
3. `src-tauri/src/find.rs::search_with_extension`: отделить источник кандидатов от общего `name_score`, `usage_boost`, лимита результата и ранжирования. На полном наборе fuzzy-проход 2,66 с, поэтому перед нечётким сравнением нужен индекс префиксов/триграмм или ограничение fuzzy-кандидатов.
4. `src-tauri/src/dispatch.rs::dispatch_find` и `src-tauri/src/lib.rs::run`: передать менеджер индекса в поиск и запускать сканирование/watchers в отдельном worker, не в аудиопотоке. В `src-tauri/src/commands_api.rs` добавить команду статуса/перезапуска индекса.
5. `frontend/app.js`: добавить источник в группу настроек поиска и показывать `Индексируется C: · N файлов и папок` без выдуманного процента; для `auto` пока доступен Everything — продолжать поиск через него. В локальном режиме до первого завершения сообщать, что поиск появится после первичной индексации. Добавить переводы для новых подписей в `frontend/i18n/locales/*.js`; в `src-tauri/resources/settings.json` — значение по умолчанию.

## Наблюдения по API Windows

`ReadDirectoryChangesW` открывает handle каталога с `FILE_FLAG_BACKUP_SEMANTICS`, следит за деревом и отдаёт конкретные изменения; на переполнение буфера требуется перескан. Для получения самих изменений Microsoft рекомендует этот API вместо уведомителя, который сигнализирует только о факте изменения [Directory Change Notifications](https://learn.microsoft.com/en-us/windows/win32/fileio/obtaining-directory-change-notifications).
