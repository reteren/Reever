# Английская ASR-модель: 0.6B против 110M

## Краткий вывод

Для `ru+en` оставить Parakeet TDT 0.6B v2 int8: на синтетическом английском с сильным русским акцентом он точнее распознавал команды и названия. Для «только английский» поставить Parakeet TDT 110M int8 как более быструю и компактную модель по умолчанию; оставить 0.6B как вариант для речи с сильным акцентом. Выбор следует считать предварительным: набор мал и синтезирован, поэтому перед выпуском стоит проверить его на голосе пользователя.

## Методика

Создан корпус из 48 WAV: 24 фразы по два голоса Windows SAPI (`Microsoft Zira Desktop - English (US)` и `Microsoft Irina Desktop - Russian`, обе читают английский текст). В нём 18 команд, включая `river open notepad`, `river close discord`, другие названия программ, поиск и системные команды, и 6 предложений для диктовки. Формат — 16 кГц, mono, PCM16; суммарная длительность 182,255 с. Для проверки контура Engine отдельно синтезированы 36 команд с русским wake-word «ривер» двумя русскими голосами.

Обе основные модели прогнаны существующим `src-tauri/examples/asr_bench.rs` в release, 4 потока, на том же корпусе. WER/CER считаются после нормализации регистра и пунктуации. Точное имя приложения — наличие ожидаемого названия приложения в распознанном тексте для 13 команд с приложениями на голос, всего 26 случаев. Дополнительно `en_engine_probe` проверил события команд в Engine, а `en_moonshine_bench` — альтернативные семейства напрямую через Sherpa. Размер — сумма файлов модели на диске; память — пик working set отдельного процесса бенчмарка, не всего Reever. Время загрузки зависит от файлового кэша ОС. Все WAV и скачанные для сравнения модели лежали во временной папке вне репозитория.

## Parakeet 0.6B и 110M

| Показатель | Parakeet TDT 0.6B v2 int8 | Parakeet TDT 110M int8 |
|---|---:|---:|
| Модель на диске | 630,8 МиБ | 130,4 МиБ |
| Экономия относительно 0.6B | — | 500,4 МиБ (79%) |
| Загрузка в наблюдавшихся запусках | 1,4–1,8 с | 0,7–1,1 с |
| Декодирование, 182,255 с аудио | 10,544 с; RTF 0,058 | 3,373 с; RTF 0,019 |
| Пиковый working set одного процесса | 795,6 МиБ | 318,7 МиБ |
| WER / CER, все 48 WAV | 0,225 / 0,105 | 0,257 / 0,132 |
| WER команд, 36 WAV | 0,407 | 0,483 |
| WER диктовки, 12 WAV | 0,125 | 0,134 |
| Точное название приложения | 16/26 (61,5%) | 15/26 (57,7%) |

110M декодировал этот набор примерно в 3,1 раза быстрее. В отдельном процессе его пиковый working set был на 476,9 МиБ (60%) ниже; это не замер полной памяти Reever с обеими ASR-моделями. Потеря точности сосредоточена в командах: WER выше на 7,6 п.п.; на диктовке разница WER — 0,9 п.п.

| Голос | Модель | Точное имя приложения | WER команд |
|---|---|---:|---:|
| Zira, английский SAPI | 0.6B | 11/13 | 0,051 |
| Zira, английский SAPI | 110M | 11/13 | 0,051 |
| Irina, русский SAPI читает по-английски | 0.6B | 5/13 | 0,763 |
| Irina, русский SAPI читает по-английски | 110M | 4/13 | 0,915 |

В прямой проверке Engine с английским wake-word `river` Zira дала 18/18 событий команды на обеих моделях; Irina — 6/18 на 0.6B и 2/18 на 110M. С русским wake-word в режиме `ru+en` обе модели дали событие команды для 35/36 WAV. Это проверка сгенерированных WAV и текущей грамматики, а не тест пользовательской речи или фактического запуска приложений. Точные маршруты приложений не сравнивались: список действий в локальном `actions.json` менялся во время исследования.

## Другие модели Sherpa-ONNX

Все оценки качества ниже сделаны на тех же 48 WAV. Размер пакета включает извлечённые файлы; там, где пакет содержит и FP32, и int8, отдельно указан размер выбранных int8 весов с токенами.

| Модель | Размер | WER всего / Zira / Irina | Скорость и загрузка | `Asr::new` сейчас |
|---|---:|---:|---|---|
| Zipformer small en offline | 117,0 МиБ пакет; 26,3 МиБ int8 ONNX + tokens | 0,464 / 0,162 / 0,766 | RTF 0,011; загрузка 0,96 с | Нет: прямой Sherpa-конфиг работает, но текущий загрузчик задаёт `nemo_transducer` и падает на metadata. |
| Moonshine tiny en int8 (v1) | 119,0 МиБ | 0,533 / 0,090 / 0,976 | RTF 0,010; 0,59 с | Нет: нужен отдельный конфиг Moonshine. |
| Moonshine tiny quantized (релиз 2026-02-27) | 42,4 МиБ | 0,539 / 0,096 / 0,982 | RTF 0,008; 0,37 с | Нет: нужен отдельный конфиг Moonshine. |
| Moonshine base quantized (релиз 2026-02-27) | 134,9 МиБ | 0,497 / 0,066 / 0,928 | RTF 0,014; 0,65 с | Нет; ONNX Runtime завершил с ошибкой 3 из 48 клипов, поэтому оценка качества ненадёжна. |
| NeMo Conformer CTC small int8 | 126,4 МиБ пакет; 44,3 МиБ `model.int8.onnx` + tokens | 0,473 / 0,132 / 0,814 | RTF 0,014; 0,63 с | Да: текущая ветка CTC `model*.onnx` + `tokens.txt`. |
| Whisper tiny.en | 244,7 МиБ пакет; 98,8 МиБ выбранные int8 веса + tokens | 0,551 / 0,144 / 0,958 | RTF 0,037; 0,33 с | Да: текущая ветка Whisper. |

Из проверенных альтернатив CTC small и Zipformer получили лучшее общее WER после 110M, но уступили на голосе Irina; Zipformer также требует небольшой правки определения семейства модели в загрузчике. Whisper tiny.en и оба Tiny Moonshine заметно хуже на смешанном корпусе. Малый пакет Moonshine tiny привлекателен размером, но качество здесь не подходит как универсальная замена. Новые Rust-зависимости не нужны: crate `sherpa-onnx` в проекте уже предоставляет нужные типы, потребуется только отдельная конфигурационная ветка.

## Рекомендация и изменения для этапа 2

1. **`ru+en`: оставить 0.6B int8** в качестве английской второй модели. По измеренным SAPI данным он лучше удерживает английские команды при русской артикуляции. Переход на 110M экономит около 500 МиБ на диске и порядка 477 МиБ peak working set в одно-модельном замере, но повышает WER команд с 0,407 до 0,483.
2. **«Только английский»: выбрать 110M int8 по умолчанию**, сохранив 0.6B как вариант повышенной точности. Для английского голоса Zira обе модели дали 18/18 командных событий; прямой ASR одинаково точно распознал название приложения в 11/13 случаях. 110M немного повышает общий диктовочный WER, зато значительно ускоряет декодирование и снижает память.
3. Для двух разных значений по умолчанию конфигурации нужен отдельный выбор модели английского режима: сейчас `second_asr_model` используется и как вторая модель в `ru+en`, и как основная модель, когда русский отключён. На этапе 2 обновить `src-tauri/src/config.rs` (`Settings`, значения по умолчанию и `primary_asr_model()`), `src-tauri/src/recognizer.rs` (`run_inner()`/`enable_second_language()` при разделении путей), `frontend/app.js` (настройка языковой модели), `src-tauri/src/commands_api.rs::list_asr_models()` при необходимости UI-списка и `scripts/fetch-deps.ps1` (скачивание и выбор модели). Само подключение Parakeet 110M уже работает в текущем `src-tauri/src/asr.rs::Asr::new()`; для Zipformer/Moonshine понадобится добавить распознавание семейства/соответствующую конфигурацию в эту функцию.

Результаты не заменяют проверку реального микрофона: корпус короткий, SAPI Zira и Irina не представляют все акценты, а команды подбирались вручную. Наблюдаемая разница для русской синтетической артикуляции — основание оставить запас по качеству в `ru+en`, а не прогноз точности для любого пользователя.
