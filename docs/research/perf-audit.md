# Аудит производительности Reever: вне ASR, wake, WebView и индекса

Дата: 2026-10-16 · пакет `0.3.9`.

## Методика и ограничения

- Прочитаны `recognizer.rs`, `events.rs`, `input_thread.rs`, `micwatch.rs`, `audio.rs`, `engine.rs`, `segmenter.rs`, `everything.rs`, `lib.rs` и `Cargo.toml`; пользовательские настройки прочитаны только для определения режима.
- Текущие настройки: `activation_mode=both`, `wake_spotter=true`, `partial_results=true`, `dictation_live=true`, `offline_mode=false`.
- Сняты счётчики уже работающих процессов за 60 секунд. Reever и Everything не запускались и не закрывались. Это наблюдение процесса, не контролируемый тест речи или тишины; CPU процесса Reever включает исключённые ASR/wake и Tauri, но не дочерние процессы WebView2.
- `perf_audio_config` только запросил конфигурацию устройства, не открывая аудиопоток. `perf_vad` прогнал 20 000 нулевых кадров. `perf_segmenter_alloc` прогнал по 20 000 синтетических пакетов в тихом и речевом режимах. Все замеры проб — `--release`; новые зависимости не добавлялись. Cargo-пробы собраны, тесты не запускались.
- Частоту callback CPAL нельзя снять без счётчика внутри уже работающего callback. `BufferSize::Default` не раскрывает фактический размер; второй поток захвата не открывался, чтобы не конкурировать с Reever за микрофон.

## 2. Захват, ресемплинг и VAD

Измеренная конфигурация — 48 kHz stereo F32. `audio.rs::start_capture` сводит каналы в mono и переводит 48 kHz → 16 kHz через `rubato::FftFixedInOut` с аргументом входного блока 1024. Для этой пары частот Rubato 0.15.0 округляет блок до **1026 входных кадров и 342 выходных сэмплов**: один выходной блок соответствует 21,375 ms. Средняя скорость производства таких блоков — расчётные 46,8/сек; `try_send` отправляет один `Vec` на CPAL callback, в котором появился выход, поэтому фактическая частота отправки зависит от группировки callback. Число кадров CPAL и частота callback не измерены (`BufferSize::Default`).

Аллокации в `audio.rs` при каждом callback с данными:

- `data.iter().map(...).collect()` создаёт новый `Vec<f32>`, в том числе для измеренного входа F32, где преобразование — identity.
- `mono` и `out16` переиспользуют ёмкость. Однако `StreamResampler::push` делает `drain(..need).collect()` для каждого входного FFT-блока; `rubato::process` также возвращает новые выходные векторы.
- `out16.clone()` каждый раз копирует и выделяет буфер для передачи в очередь. Неблокирующий `try_send` верно защищает аудиодрайвер от ожидания, но не устраняет копию.

**Оценка** allocator payload при непрерывном входе 48 kHz stereo: 384 KB/s для промежуточного `f32buf` + 192 KB/s для `block.collect()` + 64 KB/s для выходов ресемплера + 32 KB/s для клона PCM, итого около **672 KB/s** известных запросов памяти, без заголовков `Vec`, округления ёмкости и внутренних аллокаций Rubato. Размер каждого CPAL callback неизвестен, поэтому частоту аллокаций/сек по callback не экстраполирую.

Очередь `AUDIO_QUEUE=512` хранит `Vec<i16>`, а не фиксированный пакет. **Оценка** при одном блоке Rubato на элемент: 512 ×342×2 = около **342 KiB**, или 10,94 s звука. Callback может собрать несколько FFT-блоков в одном `Vec`, так что точный предел зависит от драйвера; комментарий `recognizer.rs` про «~5 s» этой конфигурацией не подтверждён.

VAD получает каждый кадр в Idle при wake-режиме. Измерено около 0,10 ms CPU/512 сэмплов, что даёт ~0,31% одного ядра в реальном времени. Для этого CPU бюджет низкий; отключать Silero ради экономии без изменения поведения wake невыгодно. Пауза по кнопке уже останавливает захват физически.

## 3. Фразы и горячий путь

`Segmenter` копит PCM: команда ограничена 15 s, диктовка — 24 s (soft limit 12 s), pre-roll составляет 300/500 ms. Это **оценка** примерно 480/768 KiB на рабочую фразу; при `SpeechEnd` `finish_segment()` клонирует весь буфер, затем зануляет, но сохраняет capacity исходного `Vec`. Пик около **1 MiB для команды** и **1,5 MiB для диктовки** на пару рабочий буфер + финальный клон, без очереди и ASR. Промежуточный `current_audio()` отдаётся как срез, то есть отдельной копии для чтения partial нет.

`Segmenter::push()` переносит `frame_remainder` через `mem::take`, копирует новый пакет в `buffered`, затем копирует незаконченный хвост обратно. В тишине `append_bounded()` держит pre-roll через `Vec::drain`, перед сдвигом зануляя выбрасываемые сэмплы. Синтетический allocator probe подтвердил около 2 запросов выделения на пакет; измеренное время сегментатора менее 1 μs/пакет, поэтому churn есть, но CPU не выглядит узким местом. Замена pre-roll на кольцевой буфер возможна, но выигрыш памяти мал, а риск ошибиться в границах фразы и очистке приватного аудио выше.

Без контрольной A/B сборки безопасного изменения профиля с измеренным выигрышем не найдено. `target/release/deps` содержит большие `.rlib`/`.pdb` для сборки, но это не runtime-память и не доказательство размера дистрибутива.

**Рекомендация по этапу 2:** начать с `LevelMeter::push` (не считать RMS при скрытом окне), затем убрать лишние временные буферы и клон в `audio.rs`, добавив только счётчики размера/частоты callback без захвата содержимого. Профиль release оставить как есть; `rodio` сужать только после явного WAV-контракта для пользовательских паков. Проверку интервала `keep_warm` передать в согласование с задачей 3.
